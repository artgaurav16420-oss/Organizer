# AGENTS.md

## What this is

Fermi lab PDF drawing organizer. Scans a folder of PDF drawings, extracts BOM tables / USED ON / NAME fields (with OCR fallback for scanned pages), detects watermarks, builds a parent-child graph, and copies files into a nested folder tree. Produces a timestamped `.txt` report and a live `.xlsx` workbook after every run.

**Driving it from an AI agent**: the operator runbook is the repo skill `.opencode/skills/pdf-organizer/SKILL.md` (loaded automatically when a session runs inside this repo; other agent tools can point at the same file). Keep this file as the code reference; keep the skill as the golden path (dry-run -> review -> execute), flag decisions, reporting and troubleshooting.

## Run

```bash
pip install -r requirements.txt          # plain Python >=3.10; or: uv pip install -r requirements.lock (SHA-256 pinned)
python organize_fermi_pdfs.py <folder> [--output DIR] [--dry-run] [--incremental] [--no-ocr] [--jobs N] [--rekey-titleblock]
```

- Use the repo venv: `.venv\Scripts\python.exe ...` (Python 3.11 + deps + pytest). It is uv-managed and has **no pip** (`python -m pip` fails) — install packages with `uv pip install --python .venv\Scripts\python.exe -r requirements.txt`.
- The project is installed **editable** in `.venv`, so `python -m fermi_organizer.cli` and the `fermi-organize` console script work from any cwd. Running `fermi_organizer\cli.py` directly fails on relative imports; the launcher `organize_fermi_pdfs.py` (sys.path shim) also works from any cwd.
- `--dry-run` prints actions without copying files; still writes the timestamped `.txt` report when the output folder already exists, and always rebuilds the `.xlsx` workbook unless openpyxl is missing (ImportError is caught, workbook skipped with a warning). A missing `--output` folder is not created before the run, so the `.txt` is skipped; the workbook writer then creates the folder. Always run this first (README workflow).
- `--incremental` re-processes only stems not already in the output tree (the input scan is recursive) plus stored `_orphans/` (adoption); already-organized subfolders are never re-sorted — supersede swaps and parent-adoption moves still touch them. New BOM-less standalone PDFs are parked in `_orphans/` like a full run. With the default output it targets the input folder itself — to feed an existing tree at `<input>/Output`, pass `--output <input>/Output`.
- `--no-ocr` disables Tesseract fallback for image-only PDFs.
- `--jobs N` = extraction worker processes (0=auto=CPU count, 1=serial; default 0). N>1 uses a ProcessPoolExecutor with an explicit `spawn` context (do not switch to fork — unsafe in a threaded parent, and 3.10/3.11 CI would diverge) and merges worker OCR events back into the run report.
- `--rekey-titleblock` (opt-in) trusts the title block over the filename: a **text-layer** PDF whose title-block number disagrees with its filename is re-keyed to the title-block number (revision adopted, copied file renamed) — only when no drawing of that number already exists in the run; otherwise it stays report-only. Scanned (OCR) numbers are never used to rename a file.
- Default output = **the input folder itself** (in-place). Pass `--output` to keep the tree separate (e.g. `<input>/Output`).

## Dependencies

- **PyMuPDF** — required; pinned `==1.28.2` in `pyproject.toml` / `requirements.txt`. Import as `pymupdf`, **never the legacy `fitz` shim** (the shim prints a deprecation notice through the stdout handle pymupdf captured at its import time, so it leaks into output whenever pymupdf was imported first).
- **openpyxl** — optional at runtime; only for the `.xlsx` workbook (ImportError is caught and logged, run continues). In `pyproject.toml` it is the `excel` extra (`pip install -e ".[excel]"`); `requirements.txt` still includes it.
- **Tesseract** — needed only for scanned (image-only) PDFs. Auto-detected via `TESSERACT_EXE`, then `PATH`, then common Windows dirs (Program Files, Program Files (x86), `%LOCALAPPDATA%\Programs`); only the common-dir fallback touches the process env (`OCR._export_for_pymupdf`, required because PyMuPDF's in-process OCR resolves binary + tessdata from process env with no API alternative). Our own CLI invocations never rely on that global: they get an explicit env via `OCR.subprocess_env()` (TESSDATA_PREFIX only; None = inherit when no common-dir install).
- `requirements.lock` is regenerated with `uv pip compile requirements.txt --generate-hashes -o requirements.lock` (command recorded in the lock header) whenever `requirements.txt` changes. Test/CI tooling (pytest, pytest-cov, build, setuptools, ruff) is a separate hashed lock: edit `requirements-dev.in`, regenerate with `uv pip compile requirements-dev.in --generate-hashes --universal --python-version 3.10 -o requirements-dev.txt`.
- Pin/CVE notes for deps live in README's *Licensing & dependency notes* (e.g. PyMuPDF <=1.28.2 CVE scope, Tesseract 5.5.3+); check there before bumping a pin. `SECURITY.md` and `THIRD_PARTY_NOTICES.md` are licensing/reporting docs, not run instructions.

## Architecture

```
organize_fermi_pdfs.py   — thin launcher (sys.path shim -> fermi_organizer.cli:main)
fermi_organizer/
  cli.py                 — argparse, orchestration, Excel glue (all graph/tree traversals are iterative and depth-capped at TREE_MAX_DEPTH=500, so no recursion-limit bump is needed)
  config.py              — shared regexes, constants, path/depth limits, OCR geometry
  extraction.py          — BOM/table/text/OCR extraction, USED ON, NAME, title block (number/REV/NAME), watermark detection; OCR context
  graph.py               — pure algorithms: revision ranking, matching, cycles
  naming.py              — folder naming + path-length shortening
  fsops.py               — indexing, placement, tree scans, supersede/orphan copies
  runmodes.py            — run_full / run_incremental (return the structured run context)
  report_glue.py         — tree-derived NAME fallback for the workbook
fermi_report_xlsx.py     — standalone workbook builder (openpyxl, optional)
tests/                   — pytest suite (PDFs generated at test time)
```

## Key conventions

- **Stems are canonical uppercase** (`config.canonical_stem`): the part token is located anywhere in the name (numeric prefixes like `2.20.3.9 F10196150--CHK`, trailing titles like `F10137913 KIT, ...`), hyphens become underscores (`F10187622-B-CHK` -> `F10187622_B_CHK`), and `PART_STEM_RE` (`FC?` + 5-8 digits + `[A-Z0-9_]*`) validates the result; non-part PDFs are ignored with a warning. Hyphen/underscore/prefix variants of one drawing therefore share a stem. Input scan is recursive, but only **top-level** `Output/` (case-insensitive) and `_`-prefixed dirs are skipped — a nested `sub/Output/` is scanned. Duplicate stems: shallowest path wins (input originals beat nested organized-tree copies), then lexicographic order.
- **Revision ranking**: CHK (unapproved) < no-revision < A < B < … CHK stems rank below all DWG stems but still order among themselves.
- **BOM is the only source of truth** for parent-child edges. USED ON is a cross-check only, never a placement source: a child whose USED ON names a parent the parent's BOM does not list is a **USED ON bug** (reported, not placed). The reverse (BOM lists a part but its USED ON omits the parent) is also flagged.
- **Same-revision duplicates** (two PDFs with the same canonical stem): resolution runs **before** extraction (both run modes) so BOM/NAME/title block come from the copy that will be placed. Ranking: non-watermarked > text-layer > shallowest > lexicographic. Watermarked losers are archived in `_superseded/` only when a clean copy exists (all-watermarked → best-ranked used as-is, nothing archived); every other loser stays ignored in the input folder. "Same revision" means same canonical stem (hyphen/underscore/prefix variants of one name share it).
- **Title block check**: the drawing number, revision, and NAME printed in each scanned PDF's own title block are compared against the filename — the bottom-most `REV`/`NUMBER` labels are the title block (the revision-history RCD block sits higher). Mismatches go to the log and the workbook `Title block check` sheet; the filename drives placement unless `--rekey-titleblock` re-keys a misnamed **text-layer** file (see Run).
- **OCR geometry / reliability quirks** (extraction.py): OCR values use a wide symmetric window and ranked candidates (exact F-number > OCR-corrected > bare digits) because Tesseract word boxes can be offset by a row. Parts-list OCR reads the bottom-up Fermilab layout (rows above the `ITEM/FERMI#` header; the title-block `FERMI NATIONAL ACCELERATOR LABORATORY` text is never the header), retries psm 6 when a row strip glues the item digit into the FERMI token, and skips RCD numbers. OCR strips are read with a few zoom/psm/oem passes and voted (a value read by two passes wins); a pipe read as the digit 1 (`FLO|44633`) is corrected (`_ocr_tok`). Scanned sheets are A0-A4 stored either at ISO page size or at the scanner's dpi (1 px = 1 pt, e.g. a 153 dpi A0 scan is a 7152x5051 pt page): OCR coordinates are normalized to ISO page points and the full-page render dpi is capped at ~300 MP (`OCR_MAX_RENDER_MP`; a fixed 300 dpi render of that page is 627 MP and PyMuPDF's OCR fails silently), and strip/zoom magnification is divided by the page scale.
- **USED ON hygiene**: the drawing's own number is dropped from its USED ON values (the box neighbours the DRAWING NUMBER box) and from its BOM rows (an OCR parts-list read can pick up the title block's own FERMI number). OCR refs that are not clean `F`+8-digit reads (wrong length, or O/I/L/S/B/pipe confusions) are snapped to a unique known stem before edges/missing are computed; a clean read is trusted as-is (a genuine missing reference must stay visible for the Teamcenter download list even when some unrelated stem sits one digit away), and ambiguous reads are left as-is.
- **Supersede archive safety** (`runmodes._swap_revision_files`): the old revision is archived with a full byte-for-byte content compare (`fsops._same_bytes`, not size/mtime — `filecmp.cmp` is avoided because it can reuse a stale path+stat verdict) and staged next to its target before `os.replace`; an archive-name collision with *different* content gets a numeric suffix (`stem.1.pdf`) — a tree copy is never overwritten unarchived. `fsops.resolve_archive_target` centralizes that rule (also used by `copy_superseded`/`copy_watermarked_duplicates`) and returns an `already` verdict: a byte-identical archive is **not re-copied** on repeat runs (the stem still counts as archived). A crash mid-swap leaves `<name>.pdf.supersede_tmp.<pid>` (does not end in `.pdf`, so scans ignore it). `fsops.sweep_supersede_staging` deletes only that exact shape, and only outside top-level `_`-prefixed dirs (dry-run reports only). No PID/age check — never run two processes against one output (the sweep would delete the other run's live staging file). Pinned by `tests/test_swap_archive_collision.py`.
- **Archive failures never retire orphans**: `copy_superseded` returns `(count, archived_stems)` — only stems whose archive copy is byte-verified present (cache-free compare: `filecmp.cmp` can reuse a stale path+stat verdict; a same-name file with different bytes or a symlink never counts, on the no-new fast path included). Incremental retirement (`fsops.retire_adopted_orphans`) may delete a parked `_orphans/` copy solely for those stems (plus `_swap_revision_files` successes), so a failed/symlink-refused archive can never delete the last copy; only a byte-identical **regular-file** live copy retires the parked copy — a symlinked live entry never counts (a link is not a managed copy) and the orphan is kept with a warning (`tests/test_fsops.py`). Folder moves (`shutil.move` in `_move_children_under_superseding` / `_place_above_organized_children`) first check `fsops.folder_foreign_pdfs`: a folder holding another drawing's PDF (or one that cannot be listed) is refused with a manual-review warning instead of relocating unrelated files.
- **Folder names**: `{base} {NAME}` (e.g. `F10126106 Assembly bracket`), sanitized for Windows **and stripped of C0/C1 control chars + bidi overrides** (`naming.sanitize_folder_name` — a NUL from a hostile PDF otherwise crashes mkdir with `ValueError` past the OSError-only guards; the place/copy guards also catch `ValueError`). Auto-shortened to stay under `MAX_PATH=250` / `MAX_DIR=240`. Shortening walks **every root-to-leaf path**: a shared sub-assembly under two parents must be shortened for both chains (`place_files` copies it under both), so never dedupe that walk by stem — cycles are broken before placement and `TREE_MAX_DEPTH` bounds the walk.
- **Output tree**: organized folders + `_orphans/` (parked, adoptable by later incremental runs; the parked copy is retired once a later run places that stem) + `_superseded/` (older revisions / unapproved CHK / watermarked duplicate losers). Input originals are never modified or deleted — only the output tree is mutated (copies, supersede swaps of tree copies, `_orphans/` retirement, staging sweep). In-place runs still leave top-level source PDFs in place.
- **Run lock** (`fsops.acquire_run_lock`, held by `run_full`/`run_incremental` via thin wrappers so it spans all returns): `<output>/.fermi_organizer.lock` (dotfile, invisible to scans) is created O_EXCL at run start and released in `finally`. A second concurrent run raises `RunLockedError` (CLI prints + exits 1) — this **enforces** the old "never run two processes" rule instead of documenting it. A lock older than 24 h is stolen with a warning (crashed runs leak it); anything younger fails closed with a recovery pointer. Steals loop the create + re-read so a double-starter race leaves exactly one holder. The CLI passes `hold_lock=True` so the lock spans report + workbook writes too (direct `run_*` callers get release-on-return). Missing output dir skips silently (first dry-run must not create the folder). Pinned by lock tests in `tests/test_fsops.py`.
- **Tree mutations are guarded, not fatal** (`fsops`): a place/copy/move/mkdir `OSError` logs a warning and the run continues; report + workbook writing is best-effort too. `place_files` refuses placement entirely above `MAX_PLANNED_COPIES` (10,000 planned copies; `PLANNED_COPIES_WARN`=1,000 warns first) by raising `PlacementRefusedError`. The cap is enforced **per run**, before any supersede/move/place (incremental pre-checks placeable new roots and excludes BOM-less parked roots). A refusal skips folder placement and supersede swaps/moves, but the bounded orphan-parking and supersede-archive copies still run (documented in `_full_place`'s docstring) — it still writes report + workbook, shows a `Placement refused` action row on the Dashboard, and `cli.py` exits 2. `tests/test_skip_guards.py` pins the per-extraction-task skip shapes (oversized page, page cap, `stat`/page-count failure → `skipped_shape` vs `skip_error`).
- **Workbook consumes a structured run context** — `run_full`/`run_incremental` return the counters/lists/names (`counters, missing, chk, orphans, roots, used_on_mismatches, used_on_bugs, titleblock_mismatches, scanned, watermarks, names, placement_refused`) that `cli.py` feeds to the Excel workbook directly; the `.txt` log is user-facing only and is no longer parsed. Extraction warning counts come from the scan results (`_scan_boms`/`_scan_organized` return them; no log-substring counting), and the run timestamp is passed explicitly to `_refresh_workbook` (`cli.py`), never recovered from a log line. `used_on_bugs` lists children whose USED ON names a parent the parent's BOM does not list; `titleblock_mismatches` lists `(stem, field, filename value, title-block value)` rows; `scanned` lists image-only PDFs (recorded even with `--no-ocr`); `watermarks` lists detected watermark evidence. Folder names are still read for the NAME fallback (`report_glue.names_from_tree`).
- **Workbook state**: `<output>/organize_fermi_report.xlsx` plus a sidecar `<xlsx>.history.json`; Run History survives rebuilds only via the sidecar. PDF-derived strings must pass `fermi_report_xlsx._inert_text` (a leading `=` is forced to text — formula injection). Layout contract pinned by tests: header row 1, data from row 2, Dashboard `B5`/`B6`, sheet names/order. Do not add formula cells fed by drawing text.
- Notable behavior changes go in `CHANGELOG.md` (`## <version> — <date>`, `###` groupings), per release not per commit — check git log for undocumented changes.
- **Automation/bot PR intake** (this repo merges agent-authored PRs): a bot PR must
  touch only files related to its stated fix — `uv.lock` and other tool artifacts
  are not tracked here (`requirements.lock` is the only runtime CI lockfile;
  `requirements-dev.txt` is the only dev-tooling CI lockfile) and get
  rejected, not merged-then-deleted. A `perf:` change needs a before/after number
  in the PR body (`python tests/test_benchmark_fsops.py` prints the reference
  timings; they are informational — do not assert them in CI, shared runners are
  too noisy). Review-response work commits per finding ID, keeping docs/CI edits
  out of `fix:` commits, and security neutralizations get their own commit (never
  mixed with cosmetic polish).

## Testing

- Full suite: `.venv\Scripts\python.exe -m pytest -q` (local, seconds, no services). Single file: `... -m pytest tests/test_graph.py -q`; single test: `... -m pytest "tests/test_graph.py::test_name" -q`.
- Fixtures generate PDFs at test time via PyMuPDF (`make_pdf` in `tests/conftest.py`: one page, text lines from (72,72), fontsize 11, 16 pt line step — extraction tests depend on this layout). No binary fixtures are checked in; OCR is disabled for every test (autouse fixture), so Tesseract is not needed.
- Gates in the suite:
  - `tests/test_no_dead_imports.py` fails on an unused import in `fermi_organizer/*.py`, `organize_fermi_pdfs.py`, or `fermi_report_xlsx.py`, **and** on a new top-level public function in `fermi_organizer/` without a docstring (the 9 legacy exceptions are allowlisted there — add no more).
  - `tests/test_golden_log.py` pins dry-run log output byte-for-byte: intentional user-facing message changes must update `EXPECTED` in that test.
  - `tests/test_parallel_jobs.py` pins `jobs=2` == `jobs=1` run-context parity plus the worker OCR-event merge round-trip — any extraction change must keep the parallel path identical.
  - `tests/test_decomposition.py` is the characterization suite for the 2026-09-30 decomposition (broken-cycle placement, supersede pairs, orphan retire, xlsx sheet builders). Extend it rather than starting a new file.
- Lint gate (not in the suite): `ruff check --select F,E9,B fermi_organizer tests fermi_report_xlsx.py organize_fermi_pdfs.py` (CI job `ruff`, pinned `ruff==0.16.10`; install locally with `uv pip install --python .venv\Scripts\python.exe ruff`). No formatter is enforced.
- CI: `.github/workflows/pytest.yml` runs the suite on ubuntu (Python 3.10 and 3.11, with the `--cov-fail-under=83` ratchet) and windows (3.11), installing the pinned deps from `requirements.lock` + `requirements-dev.txt` with `--require-hashes` (no editable install — `conftest.py`'s `sys.path` shim makes that work), plus a `packaging` job (wheel build + `fermi-organize --help` smoke from a foreign cwd) and the ruff job; actions are SHA-pinned. `.github/workflows/cve-watch.yml` runs weekly (Monday 09:00 UTC, plus manual dispatch): compares the PyMuPDF pin against PyPI latest and opens a `cve-watch` tracking issue on change (script: `.github/scripts/cve_watch.py`, stdlib only). The windows-latest job is what exercises the `os.name != "nt"` skip guards (MAX_PATH, `_native`, `os.replace`, symlink refusal); openpyxl tests skip if it is missing.
- Recreate the venv if missing: `uv venv --python 3.11 .venv; uv pip install --python .venv\Scripts\python.exe -r requirements.txt pytest -e .` (`-e .` restores the editable install; tests alone work without it because `conftest.py` shims the repo root onto `sys.path`).
- For end-to-end checks, run `--dry-run` against a real drawing folder and inspect the log output + `.xlsx`.
- Line-length is an informal norm only (~≤100 cols; `fermi_report_xlsx.py` has legacy long lines). No formatter is enforced — do not reformat unrelated lines.
